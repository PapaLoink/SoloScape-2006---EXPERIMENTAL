# SoloScape on Linux

The Windows batch files still work on Windows. Linux uses **matching Bash
`.sh` launchers**; Linux cannot execute `.bat` files directly without a
Windows compatibility layer.

## Requirements

- Linux x86-64 or ARM64, with Bash, find, tar, and a desktop with a graphical
  session for the native Java game and server control panel.
- A **Java 8 JDK** (not Java 11+ and not a JRE-only runtime).
- The existing `Server/cache` directory and bundled `Server/lib` JAR files.
- For automatic installation of Temurin Java 8: `python3` and `curl` or
  `wget`, plus a network connection. The JDK is SHA-256-verified and installed
  into `~/.local/share/SoloScape/java8`; no `sudo` is used.

Use **`bash`** to invoke these files, since GitHub's contents-file creation
does not preserve the executable bit. You may run `chmod +x` on your own
checkout if you prefer using `./...`.

## Quick start

Run these commands from the repository's top-level folder:

```bash
bash Start-Here-SoloScape.sh
```

Or build both components, then run the server and client together:

```bash
bash Start-Here-SoloScape.sh build
bash Start-Here-SoloScape.sh run
```

The `run` command rebuilds both components, starts the server with
`--auto-start`, waits ten seconds and launches the Java client. Keep the
terminal open; Ctrl+C stops both processes. To run each in its own terminal:

```bash
bash Server/Build-Server.sh
bash Client/Build-Client.sh
bash Server/Start-Server.sh --auto-start
# Open a second terminal:
bash Client/Play-Client.sh
```

The client writes `Client/client.log`. The server uses `Server` as its
working directory so relative cache, data, config and database paths still
work. Player saves, cache and config are **not** removed by `clean`.

## Batch-to-Bash equivalents

| Windows file | Linux equivalent |
| --- | --- |
| `Start-Here-SoloScape.bat` | `bash Start-Here-SoloScape.sh` |
| `Setup-Java-8.bat` | `bash Setup-Java-8.sh` |
| `Client/Build-Client.bat` | `bash Client/Build-Client.sh` |
| `Server/Build-Server.bat` | `bash Server/Build-Server.sh` |
| `Client/Start-Client-Dev-Mode.bat` | `bash Client/Start-Client-Dev-Mode.sh` |
| `Server/Start-Server-Dev-Mode.bat` | `bash Server/Start-Server-Dev-Mode.sh` |
| `Client/WebClient/Play-In-Browser-Or-Phone.bat` | `bash Client/WebClient/Play-In-Browser-Or-Phone.sh` |

The play launchers are also available directly at `bash Play-Client.sh`,
`bash Start-Server.sh`, `bash Client/Play-Client.sh` and
`bash Server/Start-Server.sh`. Unlike Windows, they exist from checkout and
don't need to be generated by a build.

## Live developer mode

```bash
bash Start-Here-SoloScape.sh dev
# Or in separate terminals:
bash Server/Start-Server-Dev-Mode.sh
bash Client/Start-Client-Dev-Mode.sh
```

The watcher compiles all sources on startup, builds the original HotSwap Java
agent, watches Java source changes, recompiles and reloads compatible class
edits in the running JVM. Structural changes trigger an automatic restart.
`--prepare-only` compiles the classes and agent without starting a GUI, which
is useful on CI and headless machines. The client supports
`--mcp-port 7780` and optional original client arguments.

The Bash watchers currently recompile the full module after a source change,
rather than doing the more selective compilation used by the Windows PowerShell
watchers. They use the same `build/classes` and agent paths.

## Browser and phone

Start the server first, then:

```bash
bash Client/WebClient/Play-In-Browser-Or-Phone.sh
```

Open `http://127.0.0.1:8081/` if your browser does not launch
automatically. The real Java client still runs locally to render the game.
The browser and phone only receive the frame stream and send input back. Keep
the renderer terminal open.

The original Jagex `runescape.exe` and the Internet Explorer registry
configuration are **Windows-specific**. On Linux,
`Start-Original-Client.sh` explicitly starts the browser alternative, and
`Enable-Original-Client.sh` explains that no registry configuration is needed.
These are not claims that the Windows EXE runs natively on Linux.

For remote phone access, use a local LAN or private VPN; the HTTP/WebSocket
bridge has no public-Internet authentication.

## Common problems

- **Java version incorrect:** `bash Setup-Java-8.sh` prints the chosen JDK.
  Set `JAVA_HOME` to a Linux JDK 8 folder to override discovery.
- **No client/server window:** ensure your desktop has a working
  `DISPLAY`/`WAYLAND_DISPLAY` and the required AWT/X11 libraries. A headless
  shell can compile but cannot play the normal GUI.
- **No JDK download:** install Java 8 yourself and set `JAVA_HOME`.
- **Port already in use:** stop the other server (43594) or browser renderer
  (8081) before retrying.
- **No executable permission:** use `bash path/to/script.sh`.

The automatic GitHub Actions workflow
`Verify Linux Launchers` syntax-checks every shell script, builds both Java
JARs, and prepares both HotSwap agents on Ubuntu.
